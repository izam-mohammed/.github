## In short

Shared CI for every repository under `izam-mohammed`. Its one product is a
reusable security gate, `security-scan.yml`, that a repository calls from a
short `security.yml`. It scans for secrets (blocking), vulnerable
dependencies, risky code patterns and unsafe workflows (reporting), and
writes one sticky comment on the pull request. It knows four ecosystems:
`python`, `node`, `go` and `shell`. There is no lint, test or coverage
offering yet.

## What a person can use

### The security gate

- Call it with `uses: izam-mohammed/.github/.github/workflows/security-scan.yml@<sha>`
  and `ecosystem: python | node | go | shell`
  (`.github/workflows/security-scan.yml`; usage in `README.md`; commit
  `ce1b7cc`).
- Stage 1, gitleaks on the working tree, fails the run and blocks the merge;
  on the weekly schedule it also scans full history
  (`.github/workflows/security-scan.yml` job `secrets`).
- Stage 2, osv-scanner over every lockfile, plus govulncheck when the
  ecosystem is `go` with Go 1.25 by default; reports only (job `deps`;
  Go default fixed in `ff76c48`).
- Stage 3, semgrep with default, secrets, security-audit, OWASP and CWE
  packs plus one language pack, and Dockerfile rules when a `Dockerfile`
  exists; reports only (job `sast`).
- Stage 4, zizmor over the caller's workflows; reports only (job
  `workflows`).
- Stage 5, one sticky PR comment with a row per stage and its count (job
  `report`).
- `runs-on` input for self-hosted runners; nothing needs sudo (PR `#2`,
  commit `ff8da46`).

## Under the hood

- **Shape**: one reusable workflow, five jobs, no scripts
  (`.github/workflows/security-scan.yml`).
- **Data**: none stored; reports uploaded as artifacts kept 14 days.
- **Integrations**: GitHub REST through `actions/github-script` for the PR
  comment; tool binaries downloaded from GitHub releases and PyPI.
- **Standards and CI**: no check command and no CI on this repository's own
  pull requests; pre-commit hooks locally and Dependabot for actions
  (`docs/standards.md`, `.pre-commit-config.yaml`,
  `.github/dependabot.yml`).

## Unfinished or broken

- No tests: the gate is checked only by callers' runs; nothing proves a
  change to it before it merges (`.github/workflows/` holds no workflow
  that runs here).
- No workflow correctness lint (actionlint); zizmor is run by hand. zizmor
  1.31.1 reports 0 findings, 1 suppressed, on 22/10/2026 (run from a
  scratch shell, not CI).
- semgrep and zizmor are installed unpinned with `pip install`, and
  govulncheck with `@latest`, so a run can change without a commit here.
- Ecosystems stop at four: Rust, Swift and Kotlin repositories get no
  language rulepack.
- Stages 2 to 4 cannot block, even for a caller that wants them to.
- The PR comment uses emoji status icons; harmless, noted for the banner and
  README plan only.
- Callers pin three different commits, 16 of them the first one, so most
  callers lack the Go fix and the `runs-on` input.
- No README banner; no `site/` (not applicable, see `PLAN.md`).
